Add actual native-free HTTP attempts to infer/close/retire another client's ownership from public status; refusal must leave the owner unchanged. Normal logs do not expose nonces.
2. Loss delivery is suppressed with **context-level test routing**, including heartbeat and close during page teardown. Server records must show expiry, not explicit-close delivery, as the old owner's termination. No application bypass/debug endpoint. The held real native response is already prepared before the browser loses its token, so that fixture has no intentionally long active native computation.
3. The15s replacement target means accepted open **and first current presentation**. Record time behind a known owned nonpreemptive native job separately. Such cleanup-pending work can coexist with bounded new admission and cannot publish old data; failed/unconfirmed cleanup blocks admission. CPU controls cover both states.
4. The60s healthy proof is for a **visible** owner, following bounded second-tab setup. A long-hidden owner may expire because background timers are throttled; on return it verifies or shows expiry/retry at its own retained pose. It is not promised indefinite hidden ownership.
5. Launcher page lifetime is for pages in its **owned browser context**, not arbitrary Ctrl+N windows in a different context. Track context page/close events and finish idempotently when no owned page remains or the browser disconnects. Unit-test ordering, and use a small internal composition seam for the bounded headed check if needed; no debug HTTP endpoint.
6. Renewals require strictly increasing sequences, with remaining duration computed for the accepted request. Client permits use request-send time; late arrival cannot extend a permit. Before enabling the initial interaction permit, confirm the opened pair with a renewal so cold native startup does not consume an incorrectly double-subtracted open deadline. A reordered n+1/n test preserves the accepted deadline.

**Owner implementation clarification:** after expiry, a lost final close response may defer only the empty session record, and only after every request/payload/local retirement succeeded. It is logged as unconfirmed close, not confirmed server release. Retry still needs fresh authoritative server admission; an owned/unexpired old session refuses it. Actual request/payload/local retirement failure remains sticky and never uses this exception. CPU controls distinguish the two cases. This avoids making the frozen heartbeat/close-suppression control fail as a fictitious resource leak without weakening publication ownership or changing a criterion.

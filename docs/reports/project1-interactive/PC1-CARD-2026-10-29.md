# PC1 — preparation boundary and native replay

**Frozen card r0, 2026-10-29. Owner: Codex; challenger: Claude.**

Governing intent: the North Star charter, fixed-world clarification and step PC1 of the [move-forward plan](../../superpowers/plans/2026-10-29-atlas-browser-world-move-forward.md). This is an isolated engineering boundary; application integration and a production backend decision remain later work.

**Observable result.** Browser-facing code can request a mathematical region and distinguish prepared viewing from prepared interaction, without knowing native module paths or BW1 fixture numbers. The working native preparer remains the control.

**Riskiest assumption.** The native result contains enough stable provenance, spatial information and qualification evidence to cross that boundary without conflating world identity, approximation, collision readiness or unknown space.

**Smallest test.** Replay preserved BW1 surface, empty-air and view-context artifacts through a versioned JavaScript contract and native adapter. Compare the resulting identity, bounds, transform, representation dependencies and binary digests against the original artifacts. Exercise the lifecycle with CPU-owned resources and delayed completions. Do not regenerate geometry or run a GPU corpus for this boundary test.

**Files/ownership.** A GPU-independent contract and lifecycle live under `src/space/preparation/`, with focused registered Node units. The native adapter and replay driver live under `/mnt/ml_storage/scratch/atlas-preparation-pc1/`; they consume immutable BW1 artifacts. Publish the contract design and result in repository documentation. Existing scene codecs, persistence, renderer and navigation behavior are unchanged in this slice.

| Criterion | Decisive check |
|---|---|
| Fixed mathematical identity | Preserve `H1C-surface-child@ee2564d40bda7ef6`; stable generator/feature lineage separate from request/body/representation identity. Record canonical legacy provenance without requiring its filesystem paths as browser inputs. |
| Spatial and representation fidelity | Three-dimensional bounds and local-to-world origin/scale survive replay; declared body/view tolerances and empirical qualification limits survive without promotion to proof. Representation keys include relevant construction, builder, coverage and approximation dependencies. |
| Readiness/eligibility | Native mesh completion is `prepared`; interaction requires a separate collision/publication completion. View-only results cannot acquire navigation eligibility. Empty-air/full-solid require explicit construction classification; omitted collision data never means empty. |
| Stale/failure safety | Reject mismatched request/runtime generation, world, coverage or revision. Cancelled, unsupported and unresolved/error results grant no new coverage. A late completion after cancellation/recovery cannot publish. |
| Ownership | Executable ownership transfer and exactly-once retirement; superseded/cancelled/failed preparation releases what it owns. Shutdown invalidates pending completions and drains retirement. A disposal error remains observable, not a cleanup success. |
| View-only work | The adapter provides render buffers without invoking or requiring collision construction/restoration for view intent. This is a boundary execution check, not a claim of measured browser speedup. |
| Compatibility/process | Existing app contracts retained; focused registered units and affected CPU checks pass. No new dependencies, browser, native GPU worker or network service required for replay. Preserve all attempts and report every row. |

**Bound.** First slice at most two hours, beginning with source audit/card, then normal independent card challenge before substantial implementation. Review transmission waits are reported separately. Stop for lost provenance, an unverifiable classification treated as clearance, stale publication, unsafe ownership or inability to reproduce the boundary. A mechanical fixture problem permits a bounded replacement selected by the same criteria with the failed attempt preserved. Do not turn an unavailable sample into a world failure.

**Claim limits.** Replay tests the boundary and resource protocol. It does not establish 3D flight coverage, browser collision correctness, latency improvement, portable regeneration, cross-platform determinism or a production backend. Existing measured BW1 performance gaps remain open.

**Next owned action.** After closure, use the boundary in WC2's bounded three-dimensional preparation experiment, then integrate the resulting vertical slice through BI1's design and affected product acceptance.

## Identity and mathematical boundary

The [source codec](../../../src/space/generation/source-recipe.js) stores all real inputs as exact decimal strings. Its bounded ASCII string/integer canonical bytes are identical in the Python codec, with SHA256 keys; the implementation does not claim full RFC8785 compliance. Existing scene/FNV identities are unchanged. The resolved definition additionally binds the actual little-endian f64/C-order logical height array. A transport manifest binds the actual request/result/NPY files. File integrity is not authenticated authorship or a proof that every array element matches its claimed source.

This profile defines a bilinear sampled heightfield: its canonical grid is a mathematical input, separate from later render/collision mesh resolution. A horizontal x/z parameter chart does not assume planar terrain; height varies pointwise along y. Changing the mathematical source, grid or profile changes the definition. Observer/camera/body/cache/tessellation data are not recipe inputs. Recursive formations are absent from this profile, not silently replaced by mesh subdivision. Source coordinates are constructed exactly as rational values, rounded once on the host with a 1/1024 sample-spacing component budget, and passed directly to the unchanged no-FMA CUDA iteration kernel. Outside the domain is undefined, not empty air.

## Experience and increments

The visitor will create a world from a declared mathematical source, return to its complete definition, and explore prepared representations of that same world at supported scales. A2 supplies the generation foundation; Plane UI/multiple-world navigation are A3. Do not equate finer tessellation with additional mathematical formations.

**A2.1, this PR:** an offline, experimental parent-surface creator. Two frozen source recipes produce fresh canonical height grids with the existing distance estimator/affine interpretation, portable mathematical definitions, exact source strings, execution provenance and independent mathematical checks. It is a complete recipe for this bounded parent-only profile, not a complete migration of the current recursive Landscape. It is not loaded by the application, adds no UI/default/backend, and leaves the A1 runtime/fixtures/certificate untouched.

**A2.2, subsequent:** complete authored parent/child/grandchild/descendant lineage and imported-legacy closure; construct the needed canonical inputs from explicit choices; consume recipes through preparation, with full render/collision, identity, saved-place and scale-transition acceptance. Prove a legacy rebuild before relaxing its immutable asset binding; report mismatches without silently aliasing changed geometry. Automatic feature discovery/search is optional later work, not a prerequisite for portable authored features.

## Findings and choices

A1 owns the runtime. Upstream creation is not six independent portable scripts: the frame depends on a descent route/patch, and child construction includes root/reachability searches. Grandchild construction imports renderer/first-hit cache machinery only to consume frozen authoring outputs. The historical T1R cache reports 2407 s; that is historical source evidence, not a new benchmark. Frozen feature positions, frames and htop are explicit mathematical construction choices. Search history/cost is provenance. No creation path should rerun irrelevant experiments merely to recover those literals.

Legacy `T0` interpolates the canonical parent array, so changing that array can change the mathematical world. New A2.1 explicitly defines a bilinear sampled heightfield, with grid extent/resolution included in its construction recipe. That grid is distinct from later render/collision mesh resolution. An explicit horizontal x/z chart parameterizes a varying heightfield; it does not assume locally planar terrain. General implicit topology and projected tilted-chart reconstruction are not claimed by this profile.

## A2.1 contract

`src/space/generation/source-recipe.js` is an inert, GPU-independent codec. Input has exactly schema/version, generator id/version, exact decimal source centre (re/im), complex units per metre, canonical grid (half extent, cells per axis), affine transfer (reference distance/height, slope), and numerical policy (max iterations, coordinate rounding budget). All real quantities are decimal strings, preserved verbatim in canonical bytes; numeric JSON fields are bounded safe integers. Unsupported keys, camera/body/mesh/cache fields, nonfinite syntax and excessive lengths/exponents reject. Equivalent decimal spellings may produce distinct recipe keys in v1; no mathematical-equivalence alias is implied. Source strings never pass through JS Number. Use the existing sorted-key `canonicalJson` on this restricted ASCII schema, SHA-256 over UTF-8 canonical bytes; explicitly not a claim of full RFC8785 implementation. Python independently validates and emits identical canonical bytes/key for this string/integer domain.

The generator profile is `atlas.mandelbrot-parent-chart` / `affine-distance-r1`. Field: z <- z²+c; derivative before z; first escape at |z|>1e6; D_c=|z|ln|z|/|dz| (the existing half-Milnor convention); world D=D_c/U; only strict main-cardioid/period-2 tests prove interior. H=H_ref-slope*(D-D_ref). Sampling maps c=C+U*(x-i z), anchored at local x=z=0; rows increase z, columns increase x. Store little-endian float64 height grid, with explicit dtype/shape/order/interpolation/domain. This profile has no child formations.

The exact source and world construction produce a request key. A resolved definition additionally binds the actual logical height array (dtype/shape/order + bytes) and its integrity-checked `.npy` asset. Until successful resolution this is a source request, not an enterable world. Unknowns stay unknown; no resolved definition/height asset grants a ready surface when any required sample is unknown or failed. Iteration/rounding policy are identity-bound in v1; cross-backend mathematical equivalence is not inferred. Executable/kernel/package/device hashes and timings stay in a separate provenance record; generated mesh/collision and observer settings are absent. Same-host rebuild equality is a measured claim; cross-platform equality is unverified.

`scripts/generation/create-parent.py` loads only the new codec helper and owned `fkern.py`, invokes the existing CUDA float64 no-FMA kernel (not Python evaluation for the full grid), and creates outputs in a new exclusive scratch directory. Validate before CUDA import. Use Decimal to bound source-coordinate rounding by 1/1024 of source sample spacing and require distinct monotone coordinates. Unsupported deep scales produce a typed unsupported result with no rounded geometry. Inputs may be read from the recipe file; no old world fixture/mesh/sample input is read. CPU/mpmath is an independent bounded checker, not the production grid evaluator. Scratch-only arrays/caches/evidence; no source writes.

A portable output directory contains source request JSON, result JSON and, only on success, the `.npy` height asset. Result carries request key, resolved definition, logical asset digest plus transport hash, numeric/status summary and separate execution provenance. Relative fixed asset names, no machine paths/timestamps in mathematical identity. Moving the directory must preserve verification. Failed/unsupported/unresolved runs preserve reasons and counts and do not masquerade as worlds.

## Verification and limits

See the [frozen A2.1 card](../../reports/project1-interactive/MD2A21-CARD-2026-10-30.md) and [implementation plan](../plans/2026-10-30-atlas-md2a2-implementation.md). This does not replace or waive any maintained product gate: no product/browser acceptance is claimed. A2.2 integration must use the full maintained headed hardware gate. Existing readiness/navigation-tail/memory gaps remain open.

Prior art: [RFC8785 §3.1/Appendix D](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.1) recommends strings for numbers beyond binary64 precision; [NumPy NPY format](https://numpy.org/doc/stable/reference/generated/numpy.lib.format.html) records dtype/shape/byte order. Use numeric-only files (`allow_pickle=False`). Reuse the existing CUDA estimator and bilinear heightfield construction instead of inventing a new world conversion or mesh engine.

## Adopted numerical/output detail

The [card amendments](../../reports/project1-interactive/MD2A21-CARD-2026-10-30.md#adopted-review-amendments-before-code) are normative. Fraction-based exact host coordinate formation replaces the proposed Decimal calculation and bypasses `fkern.fdser` coordinate construction: reuse its compiled `_K` directly with host-rounded cr/ci and host interior classification. This changes no existing kernel/source. Profile constants and precise rounding/operation/status semantics are fixed there. Native supported-digit/exponent limits narrow evaluation, not exact recipe storage. Diagnostics and JIT caches stay outside the portable bundle. Legacy construction/arrays/identity remain unchanged; A2.1 does not rebuild the tilted legacy chart. Both frozen sources were selected by historical screens, which limits the generality of the result.
